# Programmatic SEO Architecture Blueprint
## 1.1 Folder & File Structure

This structure reflects a scalable Next.js (App Router) programmatic SEO architecture for the Comic Strip Creator application, supporting SSR, SSG, and ISR rendering patterns, while keeping a flat URL structure.

```
/
├── public/                 # Static assets
│   ├── robots.txt          # Automated robots.txt
│   └── og-image.jpg        # Default OpenGraph image
├── scripts/                # Utility scripts
│   └── submit-sitemap.js   # GSC Sitemap API Submission Script
├── src/
│   ├── app/                # Next.js App Router
│   │   ├── (marketing)/    # Route group for SEO pages (bypasses layouts if needed)
│   │   │   ├── templates/  # Static templates pages (SSG)
│   │   │   │   └── [category]/page.tsx
│   │   │   ├── use-cases/  # Dynamic use-case pages (SSR/ISR)
│   │   │   │   └── [slug]/page.tsx
│   │   │   ├── vs/         # Comparison pages (SSG)
│   │   │   │   └── [slug]/page.tsx
│   │   │   └── blog/       # Informational articles (SSG)
│   │   │       └── [slug]/page.tsx
│   │   ├── editor/         # Client-side Tool Page
│   │   │   └── page.tsx
│   │   ├── sitemap.ts      # Automated index sitemap generation
│   │   └── layout.tsx      # Global layout
│   ├── data/               # JSON Data Sources for Programmatic Pages
│   │   ├── seo-use-cases.json
│   │   ├── seo-blog.json
│   │   ├── seo-vs.json
│   │   └── seo-templates.json
│   ├── lib/                # Utility Functions
│   │   └── seo.ts          # Metadata and Canonical tag helpers
│   └── config.json         # Global site configuration
```

## Technical Specifications

### Hybrid Rendering Strategy
- **Client-Side:** The main `/editor` route runs fully client-side.
- **SSG (Static Site Generation):** Applied to informational pages (blog, vs) and static template categories to ensure maximum Core Web Vitals performance.
- **SSR/ISR (Incremental Static Regeneration):** Applied to highly dynamic use cases and tools, where content frequently changes or is generated programmatically on demand.

### Flat URL Structure
All programmatic pages are placed at the root level using route groups (e.g., `/use-cases/education`, `/vs/comic-strip-vs-storyboard`) to minimize crawl depth and maximize link equity distribution. Deep nesting (greater than 3 levels) is strictly avoided.

### Dynamic Sitemap Generation
- `/sitemap.xml` points to all programmatic and static routes.
- Next.js dynamic `sitemap.ts` generates sitemap items with appropriate `<lastmod>`, `<changefreq>`, and `<priority>`.
- **Limitation:** Max 50,000 URLs per sitemap file. Segmented sitemaps (e.g., `sitemap-use-cases.xml`) will be introduced once scaling begins.

### Canonical Tags & Schema Markup
- Every page dynamically generates its `rel="canonical"` tag based on `NEXT_PUBLIC_SITE_URL` via `src/lib/seo.ts` (`getBaseUrl()`).
- Automated `JSON-LD` injection:
  - `WebApplication` schema for `/editor`
  - `Article` schema for `/blog/`
  - `FAQPage` schema on `/use-cases/`

### robots.txt Automation
A `robots.txt` generated dynamically via `src/app/robots.ts` restricts crawlers on preview/development Vercel URLs to prevent duplicate content, while allowing full access to `/` on the production domain.
