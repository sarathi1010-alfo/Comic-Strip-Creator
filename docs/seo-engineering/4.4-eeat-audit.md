# EEAT Signal Audit for Utility Tools

For a programmatic micro-tool ecosystem, EEAT (Experience, Expertise, Authoritativeness, Trustworthiness) is demonstrated differently than a traditional blog.

## 1. Page-Level EEAT Checklist
- [ ] **Clear Purpose:** Does the tool do exactly what the H1 says immediately?
- [ ] **No Ads Above Fold:** Are users forced to scroll past ads to use the tool? (Negative signal).
- [ ] **"How it Works" Section:** Is there a technical or plain-English explanation of the underlying process? (Demonstrates expertise).
- [ ] **Privacy/Data Statement:** For client-side tools, explicitly state: "All processing happens in your browser. No data is sent to our servers." (Massive Trust signal).
- [ ] **Output Quality:** Is the generated image high resolution without watermarks?

## 2. Site-Level EEAT Checklist
- [ ] **About Page:** Does `/about` explain who built this and why?
- [ ] **Contact Info:** Is there a clear `/contact` page with a real form/email?
- [ ] **Policies:** Are `/privacy-policy` and `/terms-of-service` linked in the footer?
- [ ] **Technical Performance:** Does the site pass Core Web Vitals? (Slow tools are untrusted tools).

## 3. Schema implementation
- Implement `SoftwareApplication` schema on the `/editor` route to define the application category, operating system requirements (Web), and price ($0).
