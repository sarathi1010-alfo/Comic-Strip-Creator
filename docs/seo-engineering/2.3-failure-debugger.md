# Indexing Failure Debugger

When Google Search Console (GSC) flags programmatic pages with indexing errors, use this diagnostic framework for the Next.js stack.

## 1. "Crawled - currently not indexed"
- **Cause:** Google successfully visited the page but decided the content wasn't valuable enough to add to the index. This is a content quality issue, not a technical issue.
- **Diagnosis:** Review the page content. Is it too thin? Does it rely heavily on boilerplate template text with only a few words changed?
- **Fix:** Inject more unique data into the programmatic template. Add a unique paragraph, integrate FAQ schema, or merge thin pages into a larger hub page.

## 2. "Discovered - currently not indexed"
- **Cause:** Google knows the URL exists (e.g., from a sitemap or internal link) but postponed crawling it to avoid overloading the site's server, or because crawl budget ran out.
- **Diagnosis:** Check GSC Crawl Stats. Are average response times high? Are you publishing thousands of pages at once?
- **Fix:** Wait. If persistent, improve server response time by moving SSR pages to SSG/ISR or configuring Edge caching. Improve internal linking to the affected pages.

## 3. "Duplicate, Google chose different canonical than user"
- **Cause:** Google thinks this page is essentially identical to another page on the site, and decided to ignore your `rel="canonical"` tag.
- **Diagnosis:** Compare the flagged page to the URL Google chose. Are they >80% identical?
- **Fix:** Either make the page content more distinct, or accept Google's consolidation and physically 301 redirect the flagged page to the chosen canonical.

## 4. "Page with redirect"
- **Cause:** The URL redirects to another URL.
- **Diagnosis:** Did you link to `example.com/page` when the canonical is `example.com/page/` (trailing slash issue)? Next.js handles trailing slashes automatically, but links might be wrong.
- **Fix:** Update all internal links to point directly to the final 200 OK destination URL.

## 5. "Blocked by robots.txt"
- **Cause:** A rule in `robots.txt` is preventing crawling.
- **Diagnosis:** Check `example.com/robots.txt`. Are you blocking the directory?
- **Fix:** Update `src/app/robots.ts` to allow the path. *Note: Ensure your Vercel preview environments are still blocked.*

## 6. "Server error (5xx)"
- **Cause:** The Next.js server crashed or timed out when Googlebot requested the page.
- **Diagnosis:** Check Vercel Logs for the specific path. Look for unhandled database connections, API rate limits, or memory leaks in `page.tsx`.
- **Fix:** Wrap API calls in `try/catch`. Ensure data sources are reliable. Increase function timeout in `vercel.json` if necessary.

## 7. "Soft 404"
- **Cause:** The page returns a 200 OK status, but Google thinks it should be a 404 (e.g., empty content, "Not found" text).
- **Diagnosis:** Does the page have content? Is client-side rendering failing, leaving an empty `<div id="__next"></div>`?
- **Fix:** Ensure critical content is Server-Side Rendered. If the page truly shouldn't exist, use `notFound()` in Next.js to return a hard 404 status code.

## 8. "Alternate page with proper canonical tag"
- **Cause:** Normal behavior. Google found a duplicate (e.g., a URL parameter `?utm_source=...`) and correctly respected your canonical tag pointing to the clean URL.
- **Diagnosis:** Verify the clean URL is indexed.
- **Fix:** None required. This is the intended behavior of a correct canonical setup.
