# Rendering Strategy Selector

For the Comic Strip Creator micro-tool ecosystem, selecting the correct rendering pattern in Next.js App Router is critical for indexing performance, Core Web Vitals, and server resource usage.

| Tool / Page Type | Recommended Strategy | Why? |
| :--- | :--- | :--- |
| **Comic Strip Editor (`/editor`)** | **CSR (Client-Side Rendering)** | Highly interactive tool requiring browser APIs (`html-to-image`, `dnd-kit`). Cannot be pre-rendered on the server effectively due to heavy DOM manipulation. |
| **"List of Best Comic Fonts" Article (`/blog`)** | **SSG (Static Site Generation)** | Content is completely static and changes rarely. SSG offers the fastest TTFB (Time to First Byte) and requires zero server compute on request. |
| **Use Case Pages (`/use-cases/[slug]`)** | **ISR (Incremental Static Regeneration)** | Semi-dynamic content. Generates static pages initially but allows background regeneration (e.g., every 24h) when new data is added to the data source without requiring a full site build. |
| **Comparison Tools (`/vs/[slug]`)** | **SSG (Static Site Generation)** | Fixed programmatic data (e.g., Feature A vs Feature B). Highly cacheable at the Edge. |
| **User Gallery/Showcase** | **SSR (Server-Side Rendering)** | If user-generated content is added frequently and requires instant indexing and real-time freshness. |

---

## Code Implementation Patterns

### 1. CSR (Client-Side Rendering) - The Editor
Used for the interactive tool.

```tsx
// src/app/editor/page.tsx
"use client";

import { useState, useEffect } from "react";
// ... Client-side dependencies

export default function EditorPage() {
  const [mounted, setMounted] = useState(false);

  useEffect(() => {
    setMounted(true);
  }, []);

  if (!mounted) return null; // Prevent hydration mismatch

  return <ComicEditor />;
}
```

### 2. SSG (Static Site Generation) - Blog / Informational
Used for pure informational content.

```tsx
// src/app/blog/[slug]/page.tsx
import { notFound } from "next/navigation";
import blogData from "@/data/seo-blog.json";

// 1. Generate all possible static paths at build time
export async function generateStaticParams() {
  return blogData.map((post) => ({
    slug: post.slug,
  }));
}

// 2. Render the static page
export default function BlogPost({ params }: { params: { slug: string } }) {
  const post = blogData.find((p) => p.slug === params.slug);

  if (!post) return notFound();

  return (
    <article>
      <h1>{post.title}</h1>
      <p>{post.content}</p>
    </article>
  );
}
```

### 3. ISR (Incremental Static Regeneration) - Use Cases
Used for programmatic pages that update periodically.

```tsx
// src/app/use-cases/[slug]/page.tsx
import { notFound } from "next/navigation";
import useCasesData from "@/data/seo-use-cases.json";

// Optional: Pre-render top 100 paths, ISR the rest
export async function generateStaticParams() {
  return useCasesData.slice(0, 100).map((uc) => ({
    slug: uc.slug,
  }));
}

// Revalidate this page every 24 hours (86400 seconds)
export const revalidate = 86400;

export default function UseCasePage({ params }: { params: { slug: string } }) {
  const useCase = useCasesData.find((uc) => uc.slug === params.slug);

  if (!useCase) return notFound();

  return (
    <main>
      <h1>{useCase.h1}</h1>
      <p>{useCase.description}</p>
    </main>
  );
}
```
